## What it does

- Panel below Start Game / Quick Race: live server status ("N riders
  online" / "Server offline"), **Host a room**, **Join with a code** (code or
  pasted invite link, validated against the room-code alphabet, Watch
  checkbox), the public room list with Join, or Watch for full/racing rooms,
  and **Browse in game**. It polls same-origin `/net/health` every 8 s while the
  launcher is visible and stops when a game starts.
- Invite links: `?room=` shows a "You're invited" banner (Join race / Watch),
  prefills the code and is removed from the address, so Start Game no longer
  silently turns into a join.
- The page starts `rr-game` with `--room CODE`, `--room @watch:CODE`,
  `--room @host` or `--room @rooms`, plus `--net-server wss://<host>/net`
  (same origin as the listed rooms). `Frontend::net_join_invite` handles the
  `@` intents (`@` is never in a code or link).
- `rr-netd` health JSON gains `public_rooms` (max 32, public only, the same
  fields as `RoomListEntry`, no build filter). The production Nginx already
  proxies `/net/health`, so no host change is needed. The next `net-deploy`
  run ships it; until then the production panel shows status but an empty list.
