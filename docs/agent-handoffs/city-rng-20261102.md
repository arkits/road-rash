## How the 955 gap was found

1. The original draws exactly one `rand()` at 955 (LCG step count). Native
   draws none.
2. Per-tick stream index comparison: a single draw every 20 ticks
   (ticks ≡ 15 mod 20) on both sides, which native skips at 955.
   A native backtrace put it in `think_pedestrian`: pedestrian 10, type 5,
   at sample 89, about 10000 Q8 ahead of the parked camera.
3. A new capture with a 0x3000 ORDER window showed the original walks that
   pedestrian at pace 4 after its first step (unloaded branch), while native
   walks it at pace 8 (loaded). `0x00438610` draws, and so `0x00440680`/`0x00440b80`
   load, only nodes on drawn slices.
4. A second capture with RANDLOG showed the next gap (1015,
   `0x004410ba`). Native's road-clear scan saw a crossing car with
   `speed` 2868. The original reads `+0x108`, which is 0 for crossing kinds.
   `0x00449ce0` also skips nodes without a slice (parked bikes).

## Fixes

- `load_pedestrian_looks`: load only when the pedestrian's slice is in
  [ring camera slice − 1, camera + 0x1e00] (the static-box reach). The
  projected-x test of `0x00438610` is not ported (labelled in source).
- `pedestrian_road_clear`: skip `!bike_slice_present` riders and use
  `car.motion.i32(0x108)` for cars.
- Proxy: `RR_ORACLE_ORDER_RANGE` (default 0x1000 unchanged).
